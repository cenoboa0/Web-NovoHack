Dominio 3 · Consulta rápida

Glosario del Dominio 3

Los términos clave de la adquisición, el desarrollo y la implementación de sistemas de información, reunidos en un solo lugar para repasar antes del examen final del Dominio 3.

Caso de negocio

Documento que justifica la inversión en un proyecto de sistemas, comparando costos, beneficios y riesgos frente a los objetivos de negocio.

ROI

Retorno sobre la inversión: compara los beneficios obtenidos frente a la inversión realizada en un proyecto.

Estudio de factibilidad

Análisis en seis pasos que determina si un proyecto propuesto es viable técnica, operativa y económicamente antes de aprobarse.

SDLC

Ciclo de vida del desarrollo de sistemas: conjunto de fases que van desde la definición de requisitos hasta la implementación, con una bifurcación entre comprar (buy) y construir (build).

Especificación de requisitos

Documento que define de forma clara y verificable qué debe hacer el sistema, base para diseñar, adquirir y probar la solución.

RFP

Request for Proposal (petición de propuestas): documento formal enviado a proveedores para solicitar ofertas comparables sobre una solución de hardware o software.

Prueba unitaria

Verifica el funcionamiento correcto de un componente o módulo de forma aislada.

Prueba de interfaz/integración

Verifica que los distintos módulos o componentes del sistema funcionan correctamente entre sí.

Prueba de sistema

Evalúa el sistema completo frente a sus requisitos funcionales y no funcionales.

Prueba de aceptación

Confirma, junto al usuario final, que el sistema cumple los requisitos de negocio antes de pasar a producción.

QAT

Quality Assurance Testing: prueba técnica orientada a verificar que el sistema cumple los estándares de calidad, normalmente ejecutada por el equipo técnico.

UAT

User Acceptance Testing: prueba ejecutada por los usuarios finales para confirmar que el sistema satisface sus necesidades de negocio.

Prueba alfa

Prueba interna realizada por el propio equipo de desarrollo antes de liberar el producto a un grupo externo.

Prueba beta

Prueba realizada por un grupo externo de usuarios reales antes del lanzamiento general del producto.

Prueba piloto

Implementación del sistema en un subconjunto reducido y representativo de usuarios o ubicaciones antes del despliegue total.

Prueba de caja blanca

Examina la lógica interna y el código del programa, requiere conocimiento de su estructura.

Prueba de caja negra

Evalúa el sistema únicamente por sus entradas y salidas, sin conocimiento de su lógica interna.

Prueba de función/validación

Confirma que el sistema realiza correctamente las funciones para las que fue diseñado.

Prueba de regresión

Verifica que un cambio reciente no haya introducido errores en funcionalidades que antes trabajaban correctamente.

Prueba en paralelo

Ejecuta el sistema nuevo y el sistema anterior de forma simultánea, comparando resultados para validar la migración.

Prueba de sociabilidad

Verifica que el nuevo sistema convive correctamente con otros sistemas existentes sin generar conflictos.

Enfoque bottom-up

Estrategia de prueba que comienza por los componentes de nivel más bajo y avanza hacia los módulos superiores.

Enfoque top-down

Estrategia de prueba que comienza por los módulos de nivel superior y desciende hacia los componentes de detalle.

Integridad referencial

Garantiza que las relaciones entre tablas de una base de datos permanezcan consistentes (por ejemplo, que no existan claves foráneas huérfanas).

Gestión de configuración

Disciplina que identifica, registra y controla los elementos de configuración afectados por un cambio, incluyendo el punto de retorno si el cambio falla.

Gestión de cambios

Proceso formal para identificar, autorizar, implementar y registrar cambios en los sistemas, preservando su integridad.

Segregación de funciones (desarrollo/producción)

Control que impide que el mismo personal que desarrolla el código tenga también acceso para moverlo a producción.

Migración de datos

Proceso de trasladar datos del sistema anterior al nuevo, con riesgo de pérdida, duplicación o corrupción si no se planifica y valida adecuadamente.

Plan de reversión (rollback)

Documentación que describe cómo volver al estado o sistema anterior si la implementación falla.

Cambio en paralelo

Técnica de cutover que ejecuta el sistema antiguo y el nuevo al mismo tiempo durante un período, antes de retirar el anterior.

Cambio en etapas (phased)

Técnica de cutover que implementa el nuevo sistema de forma gradual, por módulos o ubicaciones, recomendada para entornos de TI grandes o complejos.

Cambio abrupto (directo)

Técnica de cutover que sustituye el sistema anterior por el nuevo de una sola vez, sin período de convivencia entre ambos.

TCO

Costo total de propiedad: suma de todos los costos asociados a un sistema durante toda su vida útil, no solo su adquisición inicial.

Revisión posterior a la implementación

Evaluación realizada tras un período de uso del sistema para medir si se cumplieron los objetivos, costos y beneficios previstos.

Cierre del proyecto

Secuencia formal de actividades al final de un proyecto: temas pendientes, custodia de contratos, documentación, lecciones aprendidas y revisión final.

Lecciones aprendidas

Conocimiento capturado al cierre de un proyecto para evitar repetir los mismos problemas en proyectos futuros.

Mantenimiento del sistema

Etapa posterior a la implementación centrada en la gestión continua de cambios sobre el sistema en producción, preservando la integridad del código y los ejecutables.
