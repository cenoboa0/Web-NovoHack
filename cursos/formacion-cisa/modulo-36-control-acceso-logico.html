Control de acceso lógico

El acceso lógico es la puerta digital a los datos y sistemas de una organización. Este módulo recorre las rutas por las que se puede llegar a esa puerta, cómo se decide quién la puede abrir (identificación, autenticación y autorización), los modelos de control de acceso y los pasos que sigue el auditor de SI para poner a prueba todo el esquema.

≈14 min de lectura I&A, MAC/DAC y auditoría

1 Acceso lógico y sus exposiciones

El acceso lógico es el proceso de autorizar a los usuarios, programas o procesos el acceso a los recursos de un sistema de información. Un control deficiente expone a la organización a riesgos como la fuga de datos y el apagado no autorizado de equipos.

Fuga de datos

Sustracción deliberada o accidental de información sensible fuera de los canales autorizados.

Apagado del equipo

Interrupción no autorizada del sistema, con impacto directo en la disponibilidad del servicio.

2 Rutas de acceso lógico

Un usuario puede llegar a un sistema de información por distintos caminos, cada uno con su propio perfil de riesgo:

  • Ruta directa: conexión local mediante una terminal conectada directamente al sistema.
  • Red de área local (LAN): acceso desde un puesto de trabajo conectado a la red interna de la organización.
  • Acceso remoto: conexión desde fuera del perímetro de la organización, habitualmente a través de internet o una VPN.

3 Funciones del software de control de acceso

Nivel de sistema operativo

Restringe el acceso a archivos, dispositivos y recursos gestionados directamente por el sistema operativo.

Nivel de base de datos/aplicación

Restringe el acceso a registros, campos o funciones específicas dentro de una aplicación o base de datos.

Tipos de control de acceso

Control de acceso obligatorio (MAC)

El sistema, no el usuario, determina el acceso en función de etiquetas de clasificación; el propietario de los datos no puede modificarlo libremente.

Control de acceso discrecional (DAC)

El propietario de los datos decide quién puede acceder a su información y con qué nivel de permiso.

4 Identificación, autenticación y autorización

El proceso de I&A (identificación y autenticación) verifica que un usuario es quien dice ser antes de concederle acceso. Sus vulnerabilidades más comunes incluyen contraseñas débiles, fáciles de adivinar o compartidas entre usuarios.

  • Login y contraseña: el método más común, pero también el más vulnerable si no se combina con otras medidas.
  • Tokens: dispositivos físicos o virtuales que generan códigos de un solo uso.
  • Biometría: huella dactilar, reconocimiento facial o de iris, entre otros factores físicos.
  • Autenticación multifactor (MFA): combina dos o más factores (algo que se sabe, se tiene o se es).
  • Inicio de sesión único (SSO): permite autenticarse una sola vez para acceder a múltiples sistemas.

Una vez autenticado, la autorización determina qué puede hacer el usuario, aplicando el principio de privilegio mínimo mediante listas de control de acceso (ACL) que especifican los permisos concedidos sobre cada recurso.

5 Seguridad del acceso remoto

El acceso remoto amplía la superficie de ataque de la organización y conlleva riesgos particulares:

  • Interceptación de las comunicaciones en tránsito.
  • Uso de redes no confiables o dispositivos personales no gestionados.
  • Autenticación débil en el punto de entrada remoto.

Entre los controles habituales se incluyen las redes privadas virtuales (VPN) cifradas, la autenticación multifactor y las políticas de acceso remoto documentadas.

6 Auditoría del acceso lógico

El auditor de SI evalúa el control de acceso lógico siguiendo, entre otros, estos pasos:

  • Obtener una comprensión general de los riesgos de seguridad que enfrenta el procesamiento de información.
  • Documentar y evaluar los controles sobre las posibles rutas de acceso al sistema.
  • Probar los controles sobre las rutas de acceso para determinar si están en funcionamiento y son efectivos.
  • Evaluar el entorno de control de acceso para determinar si los objetivos de control se están cumpliendo.
Idea clave: ningún método de autenticación es infalible por sí solo; la defensa efectiva combina varios factores y revisa periódicamente que los permisos otorgados sigan correspondiendo a la función real del usuario.
