Computación de usuario final y gestión del rendimiento de los sistemas

No toda la tecnología que procesa información de negocio pasa por el control formal de TI. Este módulo examina las aplicaciones que los propios usuarios construyen para resolver necesidades puntuales, y luego recorre las revisiones periódicas que el auditor de SI realiza sobre el hardware, el sistema operativo y las bases de datos que sí forman parte del entorno controlado.

≈16 min de lectura EUC y revisiones de rendimiento

1 Computación de usuario final (EUC)

La computación de usuario final (End-User Computing, EUC) se refiere a aplicaciones —hojas de cálculo, bases de datos de escritorio, macros— desarrolladas por los propios usuarios de negocio fuera del ciclo formal de desarrollo de TI.

Beneficios

  • Implementación rápida de aplicaciones.
  • Permite que las organizaciones sean más ágiles.
  • Retira un poco de la presión sobre el área de TI.

Riesgos

  • Puede no estar sujeta a una revisión independiente.
  • Puede no tener una estructura de departamento formal.
  • Puede contener errores y brindar resultados incorrectos.
  • No está sujeta a la gestión de cambios o de versiones, lo que genera múltiples copias, tal vez, diferentes.
  • No es segura.
  • No se realizan copias de seguridad.

Riesgos para la seguridad de los sistemas de los usuarios finales

ÁreaRiesgo típico
AutorizaciónEs posible que no exista un mecanismo seguro para autorizar el acceso al sistema.
AutenticaciónEs posible que no exista un mecanismo seguro para autenticar usuarios para el sistema.
Registros de auditoríaNo está disponible en las soluciones de EUC estándar (por ejemplo, Microsoft Excel, Access, etc.).
EncriptaciónLa aplicación puede contener datos sensibles que no se encriptaron ni protegieron.
Para el examen: ante software personal o EUC no autorizado que la política de seguridad no prohíbe explícitamente, la mejor recomendación del auditor de SI suele ser que la política se actualice para incluir un lenguaje específico al respecto, en lugar de imponer controles técnicos sin una base normativa clara.

2 Gestión del rendimiento de los sistemas

Más allá de las aplicaciones de usuario final, el auditor de SI revisa periódicamente el hardware, el sistema operativo y las bases de datos que sostienen el procesamiento formal de la organización.

Revisiones de hardware

Plan de adquisición y ejecución de hardware

Verifica que la compra e instalación de equipos siga un proceso formal y justificado.

Gestión de activos de TI

Confirma que el hardware está correctamente inventariado y clasificado.

Gestión de capacidad y monitoreo

Evalúa si los recursos de hardware son suficientes para la carga de trabajo actual y futura.

Cronograma de mantenimiento preventivo

Revisa que el mantenimiento se realice de forma planificada, no solo reactiva.

Disponibilidad de hardware e informes de utilización

Analiza el tiempo de actividad y el uso real de los equipos.

Registros de problemas e informes de contabilidad de trabajos

Revisa el histórico de incidencias y el registro de trabajos procesados.

Revisiones del sistema operativo

Procedimientos de selección de software del sistema

Verifica que el sistema operativo se eligió siguiendo un proceso formal.

Estudio de factibilidad y proceso de selección

Confirma que se evaluaron alternativas antes de adoptar la plataforma.

Software de seguridad del sistema

Revisa los controles de seguridad integrados en el sistema operativo.

Gestión de activos de TI

Verifica el inventario y licenciamiento del software del sistema.

Implementación de software del sistema

Evalúa si la puesta en producción siguió los controles de gestión de cambios.

Documentación de autorización y del sistema

Confirma que existan registros formales de aprobación y configuración.

Actividades de mantenimiento del software del sistema

Revisa parches, actualizaciones y su documentación.

Controles de cambio al software e instalación del sistema

Verifica que las modificaciones sigan el proceso formal de control de cambios.

Revisiones de la base de datos

Esquema lógico y esquema físico

Revisa la estructura de datos definida y su implementación física en el almacenamiento.

Informes de tiempo de acceso

Evalúa el rendimiento de las consultas y operaciones sobre la base de datos.

Controles de seguridad de la base de datos

Verifica los mecanismos de autenticación, autorización y cifrado.

Interfaces con otro software

Revisa cómo la base de datos intercambia información con otras aplicaciones.

Procedimientos de respaldo y recuperación ante desastres

Confirma que existan copias de seguridad probadas y planes de recuperación.

Controles de SI respaldados por la base de datos

Verifica que los controles de aplicación dependan correctamente de la integridad de los datos.

Gestión de activos de TI

Revisa el inventario y licenciamiento del motor de base de datos.
